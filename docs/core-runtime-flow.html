Core가 실제로 동작하는 순서

Core는 독립 실행 프로세스가 아니라 agyx와 cdxx가 호출하는 공유 라이브러리다. 감지·파싱·credential I/O는 CLI 어댑터가 담당하고, 공통 결정과 session transaction은 core가 담당한다.

Core first공통 정책과 계약을 먼저 선언한다.
Switch immediately확정적인 live exhaustion은 status probe를 기다리지 않는다.
Adapter boundaryCLI별 차이는 감지·파싱·저장 구현에 한정한다.

어댑터가 제공한 lock과 session control을 사용해 credential 교체를 하나의 공통 transaction으로 감싼다.

내부 실행 순서
  1. withLock 획득
  2. sessionRecords() 조회
  3. 각 session을 순차적으로 pause()
  4. afterPause() 실행
  5. 각 paused terminal에 CRLF 3회 + quota switching notice
  6. CLI 어댑터의 credential 교체 operation 실행
  7. finally에서 각 session을 순차적으로 resume()

Foreground switch와 usage 보강의 분리

Foreground

사용자가 기다리는 경로

  • live exhaustion을 switch 근거로 즉시 사용
  • 후보 선택 후 session pause → switching notice → credential 교체 → resume
  • /status 또는 /usage 결과를 await하지 않음
Background

Reset metadata 보강 경로

  • cdxx: reset 정보가 없으면 detached process에서 /status
  • agyx: child 시작 후 별도 thread에서 /usage
  • 결과는 프로필 quota 상태만 갱신하며 switch를 차단하지 않음
